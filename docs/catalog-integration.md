# Подключение фильтра каталога

Интерфейс и демонстрационная обработка товаров разделены:

- `src/js/pages/catalog.js` — открытие и закрытие панели, Escape, дополнительные поля, выбор производителей, кнопки мощности и сравнение.
- `src/js/pages/catalog-demo.js` — фильтрация и сортировка локальных карточек, счётчик результатов, сброс и демонстрационная загрузка производителя.

HTML подключает только итоговый `app.min.js`. Дополнительные модули сборка загружает автоматически; вручную подключать исходные или сгенерированные файлы с хешами не требуется.

## Отключение демонстрационного фильтра

Удалите **только `data-catalog-demo`** из формы:

```html
<form class="catalog-filter" id="catalog-filter" data-catalog-filter
      action="/catalog/" method="get">
```

`action` замените своим адресом. Сохраняйте `data-catalog-filter` и внешний `[data-catalog]`: они нужны интерфейсу. Без `data-catalog-demo` демонстрационный модуль не инициализируется и не перехватывает submit, сортировку или выдачу. Открытие панели, крестик, дополнительные поля и выбор производителей продолжают работать. «Загрузить все», обработку результатов и сброс реализует backend-разработчик.

Для отключения на уже открытой странице:

```js
const form = document.querySelector('[data-catalog-filter]');
form.removeAttribute('data-catalog-demo');
ShopEnergo.destroy(form);
```

Удаление атрибута предотвращает последующее автоматическое подключение. `destroy(form)` снимает обработчики только демонстрационного фильтра: интерфейс каталога остаётся подключённым. Скрытые и отсортированные этим модулем карточки возвращаются в исходное состояние; текущие значения полей сохраняются. После этого можно подключать собственный submit/AJAX-обработчик.

Для возврата демонстрационной обработки:

```js
form.setAttribute('data-catalog-demo', '');
await ShopEnergo.init(form);
```

## AJAX и повторная инициализация

Обработчики интерфейса делегированы контейнеру каталога. Список товаров запрашивается заново при обработке фильтра, а не сохраняется при загрузке страницы.

При замене содержимого каталога сначала снимайте обработчики, затем вставляйте ответ и инициализируйте полученный фрагмент:

```js
const catalog = document.querySelector('[data-catalog]');
ShopEnergo.destroy(catalog);
catalog.innerHTML = htmlFromServer;
await ShopEnergo.init(catalog);
```

Для замены только формы применяется та же последовательность с последующим обновлением интерфейса каталога:

```js
const catalog = document.querySelector('[data-catalog]');
ShopEnergo.destroy(catalog);
catalog.querySelector('[data-catalog-filter]').outerHTML = formHtmlFromServer;
await ShopEnergo.init(catalog);
```

Для уже изменённого фрагмента доступен `await ShopEnergo.refresh(catalog)`, который выполняет destroy и init. Перед записью ответа предпочтительнее явный destroy, чтобы очистка старого состояния не затронула новый ответ сервера.

Полностью новые контейнеры `[data-catalog]` и формы с `data-catalog-demo` также обнаруживаются существующим MutationObserver. Повторный `init` безопасен и не дублирует обработчики. Демонстрационный режим ответа определяется атрибутом новой формы; для backend-обработки не возвращайте `data-catalog-demo`.

Поля имеют обычные `name` и читаются через `new FormData(form)`. Производители передаются повторяющимся ключом `brand`: используйте `data.getAll('brand')`. Радиокнопки `catalog-sort` связаны с формой через `form="catalog-filter"`, несмотря на расположение за её пределами. Кнопки мощности обновляют `power-min` и `power-max`.

## События для собственного обработчика

Все события всплывают от формы к контейнеру каталога:

| Событие | Назначение |
| --- | --- |
| `submit` | Обычная отправка формы. Свой AJAX-обработчик может вызвать `preventDefault()` и прочитать FormData. |
| `catalog:power-change` | Пользователь выбрал мощность. `event.detail.power` — число или `null`; диапазон уже записан в поля формы. |
| `change` у `[name="catalog-sort"]` | Пользователь выбрал сортировку. |
| `catalog:filter-applied` | Отправьте после успешного обновления выдачи, чтобы закрыть мобильную панель. |
| `catalog:filter-reset` | Отправьте после собственного сброса, чтобы открыть панель и перевести фокус к мощности. |
| `catalog:brands-change` | Отправьте после изменения списка производителей, чтобы пересчитать оформление дополнительных полей. |

Пример уведомления интерфейса после успешного ответа:

```js
form.dispatchEvent(new CustomEvent('catalog:filter-applied', { bubbles: true }));
```

Внешняя интеграция отвечает за свои обработчики и запросы: `ShopEnergo.destroy` снимает только обработчики, установленные модулями сайта.

## Полная замена скрипта каталога

Если разработчик заменяет также открытие панели и остальные действия каталога, удалите `data-catalog` у контейнера и `data-catalog-demo` у формы. На уже загруженной странице:

```js
const catalog = document.querySelector('[data-catalog]');
catalog.removeAttribute('data-catalog');
catalog.querySelector('[data-catalog-filter]').removeAttribute('data-catalog-demo');
await ShopEnergo.refresh(catalog);
```

Обработчики обоих модулей каталога будут сняты. Общие вкладки и слайдеры внутри контейнера продолжат работать после refresh. Собственный скрипт отвечает за поля, кнопки и состояния панели; мобильные стили используют `data-filter-open` на `.catalog` и `data-mobile-open` на форме.
